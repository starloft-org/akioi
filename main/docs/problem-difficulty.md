# 题目难度评级与积分规则

本规则用于统一 AKIOI 题库的难度标注与积分设定，避免同一道题在不同出题人手里差出两三个档。

## 一、评级原则

评级看的是**掌握这道题所需的最低知识门槛**，不是代码长度，也不是数据规模。

三个判断维度，按优先级排列：

1. **知识门槛**：需要知道哪些算法或数据结构，是否超出基础语法
2. **思维复杂度**：是否需要建模、转化、分情况讨论
3. **实现复杂度**：细节多少、边界是否容易写挂

通过率只作为**校准参考**，不单独作为依据——新题曝光少、通过率天然偏低，不能因此判成难题。

## 二、五个等级

### 入门（10 分）

- **特征**：单一直白的逻辑，不需要算法设计，会语法就能写
- **考点**：输入输出、变量与运算、条件分支、单层循环、数组遍历、简单字符串操作
- **典型题**：A+B、求最大值、判断奇偶、统计字符出现次数
- **参考通过率**：≥ 70%
- **参考实现**：30 行以内，无嵌套数据结构

### 简单（25 分）

- **特征**：需要在几种基础方法里选对一种，但实现路径直接
- **考点**：排序、枚举、前缀和 / 差分、简单贪心、递推、栈与队列的基本应用、二维数组
- **典型题**：区间和查询、去重排序、括号匹配、日期推算、简单模拟
- **参考通过率**：50% – 70%
- **参考实现**：30 – 60 行

### 中等（50 分）

- **特征**：需要先识别出模型，再组合 1–2 个常见算法；可能出现"想得到但写不对"的情况
- **考点**：二分答案、基础 DP（线性 / 背包 / 区间）、DFS / BFS、并查集、最短路、树的基础遍历、双指针
- **典型题**：最长上升子序列、最短路模板及简单变形、二分答案 + 贪心判定、简单树上统计
- **参考通过率**：25% – 50%
- **参考实现**：60 – 120 行

### 困难（75 分）

- **特征**：需要多步推导，或把标准算法做变形、优化；单纯背模板过不了
- **考点**：树形 DP、状态压缩 DP、单调队列 / 斜率优化、线段树与树状数组、网络流基础、复杂构造
- **典型题**：树上路径统计、带修改的区间查询、DP 优化、分层图最短路
- **参考通过率**：10% – 25%
- **参考实现**：120 – 250 行

### 挑战（100 分）

- **特征**：需要非标准思路，或同时组合多个高级结构；属于"赛场上做出来能拉开差距"的题
- **考点**：可持久化数据结构、点分治 / 树链剖分、LCT、复杂数学推导、交互题、构造题、原创改编难题
- **参考通过率**：< 10%
- **参考实现**：不设上限

## 三、积分对照表

| 难度 | 默认积分 | 定位 |
| --- | --- | --- |
| 入门 | 10 | 语法练习 |
| 简单 | 25 | 基础算法 |
| 中等 | 50 | 常见算法组合 |
| 困难 | 75 | 算法变形与优化 |
| 挑战 | 100 | 高阶专题 |

系统行为：

- 新建题目时选择难度，积分自动填成上表对应的值，管理员仍可手动改
- 未选难度时按**中等（50）**处理
- 排行榜按「该题得分 ÷ 满分 × 题目积分」累计，积分调整会影响整站排名，改之前想清楚

## 四、评级与校准流程

1. **初评**：出题人按本规则给出难度与积分
2. **复核**：至少一位其他管理员确认，有分歧时取较低档
3. **校准**：上线一段时间后看真实通过率，偏差超过一个档位就调整难度，积分随之重设

边界情况处理：

- 题面很长但逻辑简单（大模拟）→ 按**思维与实现复杂度**评，不按篇幅
- 算法高级但数据极弱、暴力可过 → 降一档，避免虚高
- 同一题有多种解法时，按**预期解法**评级，而不是最强解法

## 五、存量题目迁移

已有题目的积分不会自动重算，需要时手动执行：

```sql
UPDATE problems SET points = CASE difficulty
  WHEN '入门' THEN 10
  WHEN '简单' THEN 25
  WHEN '中等' THEN 50
  WHEN '困难' THEN 75
  WHEN '挑战' THEN 100
  ELSE points END
WHERE difficulty IN ('入门','简单','中等','困难','挑战');
```

未设置难度的题目（`difficulty` 为空）保持原积分不变，建议补齐难度后再跑一次。
