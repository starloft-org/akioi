# 团队题目、个人题目与题单

题目除了「后台创建」，还可以让用户自己在站内建：团队由队长建团队题目，任何登录用户可以建个人题目。两者都用题库机制分配题号，并支持两档访问权限；题单用来把题目组织成练习清单。

## 一、题号与预置题库

| 归属 | 预置题库 | 题号示例 |
| --- | --- | --- |
| 公共题目（后台创建） | 主库（前缀 `A`，长度 4）及后台自建题库 | `A0000` |
| 团队题目 | 团队库（前缀 `T`，长度 6） | `T000000` |
| 个人题目 | 个人库（前缀 `P`，长度 6） | `P000000` |

- 题号 = 题库前缀 + 序号，序号左补零到题库的「题号长度」，在题库内递增
- 团队题目、个人题目的题库由归属自动决定，创建时不用选题库
- 这三个题库由初始化迁移写入，标记为**预置题库**：不能删除，但允许在题库管理里修改前缀与题号长度；保存后按题目原序号重新生成该题库下的所有题号（`A0002` → 改前缀 `B`、长度 6 → `B000002`）
- 后台自建题库的题号长度与前缀创建后不可修改，只能改名与备注，避免历史题号漂移
- 后台题目管理支持勾选多道题目批量「迁移到题库」：迁移后按目标题库的前缀与题号长度重新分配题号（原题号不保留），测试数据、提交记录、比赛引用都不受影响；一次最多 500 道，主库与后台自建题库都可以作为目标，团队库、个人库只放对应归属的题目，不能作为迁移目标；个人题目迁到公共题库后会转成公共题目（清空归属、访问权限改为公开），团队题目不能迁到公共题库
- 后台把题目改成团队题或个人题时，保存会按新归属重新编号

## 二、创建与归属

| 操作 | 谁能做 | 入口 |
| --- | --- | --- |
| 建团队题目 | 该团队队长 | 「我的题目 → 新建题目 → 团队题目」 |
| 建个人题目 | 任何登录用户 | 「我的题目 → 新建题目 → 个人题目」 |
| 改团队题目 | 队长 | 「我的题目 → 编辑」 |
| 改个人题目 | 创建者本人 | 「我的题目 → 编辑」 |
| 管理全部题目 | 管理员 | 「后台 → 题目管理」 |

规则：

- 一道题目只能有一个归属：公共、某团队或某用户，不能同时归属团队和用户
- 团队题目必须有归属团队；个人题目必须有归属用户
- 归属可以在后台修改，但用户端只能改题目内容和访问权限，不能改归属；团队题目也不能转给另一个团队
- 创建者删题只是软删除：题目记录与测试数据（`testcases` 记录、`TESTDATA_DIR` 下的文件）都保留，找回后仍可正常评测，详见 [data-retention.md](data-retention.md)

## 三、访问权限

| 值 | 含义 | 谁能看见 / 提交 |
| --- | --- | --- |
| `1` 公开 | 所有访客可见 | 任何人 |
| `2` 受限 | 仅团队成员 / 仅创建者 | 团队题：该团队成员；个人题：创建者本人；管理员始终可见 |

- 公共题目只能设为「公开」，受限不会生效
- 团队题、个人题默认「受限」，可以改成公开
- 个人题目、团队题目都不进公共题目列表（`/problems`）：个人题目到「我的题目」看，团队题目到「团队详情 → 题目」看，后台题目管理仍能看到全部
- 受限题目对无关用户直接访问详情会返回 403
- 提交也受同一套判断，受限题目对无关用户返回「题目当前不可提交」
- 后台创建的隐藏题（`visibility = 2`）仍然不进公开题库列表，与访问权限是两件事

## 四、题单

题单分个人题单与团队题单，不提供公开题单。

| 类型 | 谁能看 | 谁能改 |
| --- | --- | --- |
| 个人题单 | 创建者本人 | 创建者本人 |
| 团队题单 | 团队成员 | 队长 |

- 入口：「题单 → 新建题单」，选择题单归属后编辑标题、说明与题目列表
- 团队题单也可以从「团队详情 → 题单」进入
- 题单只保存题目 ID，最多 500 道；打开题单时按顺序展示仍可见的题目，无权访问的题目会被跳过
- 题单里的题目显示「已通过 / 尝试过」状态，方便安排练习
- 删除题单是软删除，不影响题目本身，题单记录仍留在库中可恢复

## 五、接口速查

用户端（都需要登录）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/my/problems` | 我的题目列表，支持 `keyword`、`kind`、`team_id`、`bank_id` 过滤 |
| POST | `/api/v1/my/problems` | 新建题目，`team_id` 非 0 即团队题目 |
| GET / PUT / DELETE | `/api/v1/my/problems/:id` | 题目详情 / 修改 / 删除 |
| GET / POST / DELETE | `/api/v1/my/problems/:id/testdata` | 测试数据列表 / 上传替换 / 清空 |
| GET / POST | `/api/v1/my/problem-sets` | 题单列表 / 新建题单 |
| GET / PUT / DELETE | `/api/v1/my/problem-sets/:id` | 个人题单详情 / 修改 / 删除 |
| GET | `/api/v1/teams/:id/sets/:sid` | 团队题单详情（成员可见） |

修改题目的 `access` 走 PUT 请求体：

```json
{
  "title": "A + B Problem",
  "access": 2,
  "team_id": 3
}
```

## 六、常见错误

| 报错 | 原因 |
| --- | --- |
| 仅团队队长或题目创建者可执行该操作 | 不是队长 / 不是创建者，也不是管理员 |
| 预置题库不能删除 | 主库、团队库、个人库由迁移写入，只能改前缀与题号长度 |
| 预置题库缺失，请检查题库管理中的主库、团队库与个人库 | 预置题库被直接改库删除，需要恢复 role 为 primary / team / personal 的三条记录 |
| 题目不能同时归属团队和用户 | 请求里同时给了 `team_id` 和 `owner_id` |
| 归属团队不存在 / 归属用户不存在 | 团队或用户 ID 写错，或已被删除 |
| 访问权限取值非法 | 公共题目传了 `access = 2` |
| 题目当前不可提交 | 受限题目，当前用户不是团队成员 / 创建者 |

## 七、题目作者

题目的作者就是**上传者**：`problems.created_by` 记录创建 / 导入这道题的用户 ID，公共、团队、个人题目都一样，团队题目不会因为归属团队就把作者显示成团队名。

- 接口返回：题目列表（公共 / 我的 / 团队 / 后台）与题目详情都带 `author_id`、`author_name`（作者用户名），前端在列表里显示「作者」列、在题面元信息里显示「作者 xxx」。
- 历史数据：早期导入的题目没有记录作者时，启动会自动回填——`A0001`–`A0009` 归用户 3，其余归用户 1；已经有作者的题目不会被覆盖。
