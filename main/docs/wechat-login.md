# 微信扫码登录（公众号方案）

站点的微信登录只依赖**微信公众号**的网页授权，不需要微信开放平台。PC 端的二维码由前端用授权链接自行生成，用户拿手机微信「扫一扫」后，在微信内完成授权即可。

## 一、公众号需要满足的条件

| 条件 | 说明 |
| --- | --- |
| 服务号且已微信认证 | 网页授权 `snsapi_userinfo` 需要认证服务号；订阅号没有网页授权权限 |
| 已设置「网页授权域名」 | 公众号后台 → 设置与开发 → 公众号设置 → 功能设置 → 网页授权域名，填站点域名（不带协议与路径） |
| 有 AppID 与 AppSecret | 公众号后台 → 设置与开发 → 基本配置 |

网页授权域名必须与用户在浏览器里访问的域名一致，否则微信会提示「redirect_uri 参数错误」。

## 二、后台配置

1. 打开「管理后台 → 系统设置」。
2. 「站点与登录」里打开「微信扫码登录」，`微信授权回调页面` 填**前端登录页地址**，例如 `https://oj.example.com/login`（不是后端接口地址）。
3. 「密钥与集成」里填公众号 `微信 AppID` 与 `微信 AppSecret`，保存并立即生效。

回调页面必须落在上面登记的网页授权域名下。授权完成后微信会把 `code` 与 `state` 追加到该地址，由前端交给后端换取用户资料。

## 三、登录流程

### PC 端（扫码）

1. 用户点「微信扫码登录」，前端向后端申请授权链接（`GET /api/v1/auth/wechat/url?from=pc`）。
2. 前端把授权链接画成二维码，同时每 2 秒轮询 `GET /api/v1/auth/wechat/status?state=...`。
3. 用户用手机微信扫码，在微信内点「允许」。
4. 微信带 `code`、`state` 跳回回调页面，前端调用 `GET /api/v1/auth/wechat/callback`，后端换取 openid 并生成登录凭证。
5. 后端把结果写入 Redis，PC 端轮询到 `authorized` 后直接登录；手机上只显示「已完成微信授权，请回到电脑继续」，不会在手机上登录。

二维码 5 分钟过期，过期后点「刷新二维码」重新生成。

### 手机端（微信内）

在微信内置浏览器打开站点时，点「微信登录」会直接跳转授权页，授权回调后在本机完成登录。

## 四、账号绑定

- 首次微信登录会按 openid 自动创建站内账号，用户名形如 `wx_xxxx`，可在「个人资料」里改昵称与密码。
- 已登录用户可以在「个人资料」里把微信绑定到现有账号；绑定关系保存在 `oauth_bindings` 表，一个微信只能绑定一个站内账号。
- 解绑后该微信再次登录会创建新账号。

## 五、常见错误

| 现象 | 原因与处理 |
| --- | --- |
| 扫码后提示「redirect_uri 参数错误」 | 回调页面域名与公众号「网页授权域名」不一致，改成一致后重试 |
| 扫码后提示「该公众号暂时无法提供服务」 | AppID/AppSecret 填写有误，或公众号没有网页授权权限 |
| PC 端一直显示「等待扫码」 | 手机上没有点「允许」，或回调页面没有正常加载；检查回调页面能否打开 |
| 提示「登录状态已失效，请重新发起」 | `state` 超过 5 分钟或被使用过，刷新二维码重新扫码 |
| 手机端扫码后跳到了站点首页 | 回调页面地址填成了首页，改成 `/login` |

## 六、相关接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/auth/wechat/url` | 申请授权链接，参数 `purpose=login\|bind`、`from=pc\|h5`、`redirect` |
| `GET /api/v1/auth/wechat/status` | PC 端轮询扫码结果，返回 `pending`、`bound` 或 `authorized` |
| `GET /api/v1/auth/wechat/callback` | 回调换取登录凭证或完成绑定，参数 `code`、`state` |
| `DELETE /api/v1/auth/wechat/binding` | 解除当前账号的微信绑定 |
