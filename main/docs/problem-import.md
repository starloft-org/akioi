# 题目导入包格式

在「后台 → 题目管理 → 导入题目」上传一个 zip 包，即可一次建好题目和测试数据。

## 一、包结构

```
题目包.zip
├── problem.md      必填，题面
├── config.json     可选，元信息
├── 1.in
├── 1.out
├── 2.in
└── 2.out
```

- 文件名固定，不要改成 `题面.md` 之类
- 测试数据可以放在子目录里，导入时只看文件名
- 不放任何 `.in/.out` 也能导入，等同于"先建题、之后再传数据"

## 二、problem.md

直接把洛谷题目页右上角**「复制 Markdown」**的内容贴进来即可，识别这些段落：

| 段落 | 来源 |
| --- | --- |
| 标题 | 一级标题 `# P1001 A+B Problem`，开头的题号会被去掉 |
| 题目描述 | `## 题目描述` |
| 输入格式 | `## 输入格式` |
| 输出格式 | `## 输出格式` |
| 样例 | `## 样例 #N` 下的 `### 样例输入 #N`、`### 样例输出 #N` 代码块 |
| 提示 | `## 提示` 或 `## 说明` |

兼容老版洛谷把输入输出合在一节的结构：`## 输入输出格式` 下用 `### 输入格式` / `### 输出格式` 分隔。

没有一级标题时，必须在 `config.json` 里写 `title`，否则导入会报"未能确定题目标题"。

## 三、config.json

可选，字段与后台新建题目一一对应：

```json
{
  "title": "A + B Problem",
  "difficulty": "入门",
  "time_limit_ms": 1000,
  "memory_limit_mb": 256,
  "points": 10,
  "tags": ["模拟", "入门"],
  "source": "洛谷 P1001",
  "visibility": 1
}
```

| 字段 | 说明 | 缺省 |
| --- | --- | --- |
| `title` | 标题，优先于题面的一级标题 | 取题面标题 |
| `difficulty` | 七级难度之一 | 留空 |
| `time_limit_ms` | 100–30000 | 1000 |
| `memory_limit_mb` | 16–2048 | 256 |
| `points` | 排行榜积分 | 按难度默认值 |
| `tags` | 标签数组 | 空 |
| `source` | 来源 | 空 |
| `visibility` | 1 公开，2 隐藏 | 1 |

难度取值：`入门`、`普及-`、`普及/提高-`、`普及+/提高`、`提高+/省选-`、`省选/NOI-`、`NOI/NOI+/CTSC`。

## 四、测试数据

- 命名 `N.in` 与 `N.out`（或 `.ans`），N 从 1 开始的正整数
- 允许跳号（1、2、5），导入后按升序重排为 1、2、3
- 每个 N 必须成对，缺一个会报「测试点 N 缺少输出文件 N.out」
- 分值不在包里配置，导入时按测试点数量均分 100 分，可在题目详情里再调

## 五、限制与常见错误

| 项 | 限制 |
| --- | --- |
| zip 大小 | ≤ `MAX_TESTDATA_MB`，默认 512MB |
| 测试点数量 | ≤ `MAX_TESTCASES`，默认 100 |
| 题号 | 无需在包内指定，导入时按 `A0000` 起自动递增分配 |

导入会先建题目再写数据，数据解析失败时题目会被自动回滚删除，不会留下半成品。带测试数据时会一并推送到已配置的评测节点，失败的节点会在返回里列出来。
