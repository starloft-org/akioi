# 题目导入包格式

在「后台 → 题库管理」建好题库，再到「后台 → 题目管理 → 导入题目」上传 zip 包，即可一次建好题目和测试数据。

## 一、先建题库

题号不再手工填写，而是由题目所属的**题库**统一分配。

1. 进入「后台 → 题库管理 → 新建题库」
2. 填题库名称
3. 填**题库前缀**，例如 `A`
4. 填**题号长度**，例如 `4`
5. 保存后这个题库的题号就是 `A` + 4 位序号：`A0000`、`A0001`、`A0002`……

规则说明：

- 题号 = 前缀 + 序号，序号左补零到「题号长度」位，题库内自动递增
- 前缀以字母开头，可带数字，最多 8 位；不同题库的前缀不能重复
- 前缀与题号长度之和不能超过 16 位
- 自建题库的**前缀和题号长度创建后不可修改**，只能改题库名称和备注，避免历史题号漂移
- 自建题库下还有题目时不能删除
- 站点初始化时会预置三个题库：**主库**（前缀 `A`，长度 4）、**团队库**（前缀 `T`，长度 6）、**个人库**（前缀 `P`，长度 6）
- 这三个预置题库不能删除，但可以在题库管理里修改前缀与题号长度；保存后会按题目原序号重新生成该题库下的所有题号
- 主库给后台创建的公共题目使用；团队库与个人库给「我的题目」里的团队题、个人题自动分配题号，后台导入题目请使用主库或其他自建题库，不要往这两个预置题库里导入

导入题目、新建题目都必须选择题库；不选时归入主库。换题库保存会把该题按新题库的规则重新编号。

## 二、包结构

```
题目包.zip
├── problem.md      必填，题面
├── config.json     可选，元信息
├── 1.in
├── 1.out
├── 2.in
└── 2.out
```

- 文件名固定，不要改成 `题面.md` 之类
- 测试数据可以放在子目录里，导入时只看文件名
- 不放任何 `.in/.out` 也能导入，等同于“先建题、之后再传数据”
- **包内不需要写题号**，`config.json` 里的 `display_id` 会被忽略，题号由所选题库自动分配
- 一次可以上传多个 zip，逐包导入，单包失败不影响其余包
- 前端会把选中的包拆成「一包一个请求」逐个上传（最多 3 个并发），弹窗按包累加「正在导入 x / y 题，成功 a 个，失败 b 个」，单包失败只影响自己
- 拆包上传让每个请求体都很小，一千题也不会撞上 nginx 的请求体上限或网关超时
- 浏览器会把这一批的文件名与导入状态记在 localStorage 里：刷新、断网或关掉页面后重新打开「导入题目」，弹窗顶部会显示「上次导入还没有完成：共 N 个，已完成 M 个，还剩 K 个」并列出剩余文件名；重新选择这些 zip 后点「开始导入」只会补导没成功的包，已成功的包不会重复导入（浏览器不保留文件本身，所以需要重新选一次），全部导入成功或点「丢弃记录」后记录才会清掉

## 三、problem.md

直接把洛谷题目页右上角**「复制 Markdown」**的内容贴进来即可，识别这些段落：

| 段落 | 来源 |
| --- | --- |
| 标题 | 一级标题 `# P1001 A+B Problem`，开头形如题号的文字会被去掉 |
| 题目描述 | `## 题目描述` |
| 输入格式 | `## 输入格式` |
| 输出格式 | `## 输出格式` |
| 样例 | `## 样例 #N` 下的 `### 样例输入 #N`、`### 样例输出 #N` 代码块 |
| 提示 | `## 提示` 或 `## 说明` |

兼容老版洛谷把输入输出合在一节的结构：`## 输入输出格式` 下用 `### 输入格式` / `### 输出格式` 分隔。

没有一级标题时，必须在 `config.json` 里写 `title`，否则导入会报“未能确定题目标题”。

## 四、config.json

可选，字段与后台新建题目一一对应：

```json
{
  "title": "A + B Problem",
  "difficulty": "入门",
  "time_limit_ms": 1000,
  "memory_limit_mb": 256,
  "points": 10,
  "tags": ["模拟", "入门"],
  "source": "洛谷 P1001",
  "visibility": 1
}
```

| 字段 | 说明 | 缺省 |
| --- | --- | --- |
| `title` | 标题，优先于题面的一级标题 | 取题面标题 |
| `difficulty` | 七级难度之一 | 留空 |
| `time_limit_ms` | 100–30000 | 1000 |
| `memory_limit_mb` | 16–2048 | 256 |
| `points` | 排行榜积分 | 按难度默认值 |
| `tags` | 标签数组 | 空 |
| `source` | 来源 | 空 |
| `visibility` | 1 公开，2 隐藏 | 1 |

难度取值：`入门`、`普及-`、`普及/提高-`、`普及+/提高`、`提高+/省选-`、`省选/NOI-`、`NOI/NOI+/CTSC`。

不在表里的字段一律忽略，写错字段名不会报错，但也不会生效。

## 五、测试数据

- 命名 `N.in` 与 `N.out`（或 `.ans`），N 从 1 开始的正整数
- 允许跳号（1、2、5），导入后按升序重排为 1、2、3
- 每个 N 必须成对，缺一个会报「测试点 N 缺少输出文件 N.out」
- 分值不在包里配置，导入时按测试点数量均分 100 分，可在题目详情里再调

## 六、限制与常见错误

| 项 | 限制 |
| --- | --- |
| zip 大小 | ≤ `MAX_TESTDATA_MB`，默认 512MB |
| 测试点数量 | ≤ `MAX_TESTCASES`，默认 100 |
| 题号 | 包内不指定，由导入时选中的题库按「前缀 + 定长序号」自动分配 |
| 导入任务 | 任务记录在内存里，保留 1 小时、最多 50 个；服务重启后进度与结果列表清空，已入库的题目不受影响 |

常见错误：

| 报错 | 原因 |
| --- | --- |
| 题目包必须是 zip 文件 | 上传了 `.rar`、`.7z` 或改后缀的压缩包 |
| 未能确定题目标题 | 题面没有一级标题，`config.json` 也没写 `title` |
| 测试点 N 缺少输出文件 N.out | 只有 `.in` 没有对应的 `.out`/`.ans` |
| 尚未创建题库，请先在题库管理中新建题库 | 题库表为空，先去「题库管理」建一个题库 |
| 题库前缀已存在 | 新建题库时前缀与已有题库重复 |

导入会先建题目再写数据，数据解析失败时题目会自动回滚（物理删除刚建的那条，避免占住题号），不会留下半成品。带测试数据时会一并推送到已配置的评测节点，推送失败的节点记录在题目详情的同步状态里。

## 七、接口说明

后台界面走「一包一个请求」的同步模式：`POST /api/admin/v1/problems/import` 只带一个 `files` 与表单字段 `wait=1`，服务端处理完这个包后直接返回结果，取 `items` 的第一个元素即可。

脚本或第三方调用也可以一次提交多个包：去掉 `wait` 即为异步模式，上传结束立即返回 `task_id`，再用下面的接口轮询进度。

```
GET /api/admin/v1/import-tasks/:task_id
```
